# Security and integrity

Do not include credentials, policy-level rows or private data in public issues. Report a reproducible security issue through GitHub private vulnerability reporting when available; otherwise contact the repository owner privately.

The API accepts a closed Pydantic schema, finite values, bounded seeds and simulation sizes, and request bodies no larger than 4096 bytes. It never accepts code, filesystem paths, SQL or remote data sources. Published files resolve through a closed artifact registry.

Public computation fails closed until platform rate limiting is qualified. The local server binds only to loopback. Cancellation stops accepting the response in the browser; it does not promise to terminate an already executing serverless computation.

An output fingerprint covers deterministic scientific results, not timestamps, durations or run UUIDs. The source commit, build commit, engine checksum and output fingerprint are distinct fields.

Dependency locks and CI checks support maintenance but do not establish absence of vulnerabilities. No final scientific release may be marked published without the required source provenance, licences and archive identity.
